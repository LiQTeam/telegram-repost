# راهنمای استقرارِ نسخه‌ی v2.1.0

## ۱. آیا وابستگیِ جدید لازم است؟
**خیر.** هیچ کتابخانه‌ی جدیدی اضافه نشد. `requirements.txt` تغییر نکرده است.

## ۲. آیا تغییر در متغیرهای محیطی (.env) لازم است؟
**اختیاری.** دو کلیدِ جدید با مقدارِ پیش‌فرضِ امن اضافه شده‌اند؛ اگر در `.env`
نباشند، خودِ کد مقدارِ پیش‌فرض را می‌گذارد:

```
# سقفِ کلِ کشِ دانلود (بایت). پیش‌فرض ۱۵۰ مگابایت. روی VPS کوچیک کمترش کن.
DOWNLOAD_CACHE_MAX_BYTES=157286400
# سقفِ حجمِ هر فایلِ دانلودی (بایت). پیش‌فرض ۶۰ مگابایت. فایلِ بزرگ‌تر رد می‌شود.
MAX_DOWNLOAD_BYTES=62914560
```

اگر ویدیوهای بزرگ‌تر از ۶۰MB می‌فرستی، `MAX_DOWNLOAD_BYTES` را بالاتر ببر — ولی
حواست به رمِ سرور باشد (چند دانلودِ موازی هم‌زمان اتفاق می‌افتد).

## ۳. آیا مهاجرتِ دیتابیس (Migration) لازم است؟
**تقریباً هیچ.** یک `UNIQUE(destination_id, hour)` به جدولِ `channel_stats`
اضافه شد. چون این جدول با `CREATE TABLE IF NOT EXISTS` ساخته می‌شود، روی
**دیتابیسِ موجود، ستونِ UNIQUE به‌صورتِ خودکار اضافه نمی‌شود** (فقط روی نصبِ تازه).
این جدول در حالِ حاضر داده‌ای ندارد (قابلیتِ «زمان‌بندیِ هوشمند» بدونِ منبعِ بازدید
غیرفعال است)، پس نبودِ constraint روی نصبِ فعلی هیچ ضرری ندارد. اگر خواستی روی
نصبِ موجود هم اعمال شود:

```sql
-- فقط اگر می‌خواهی؛ ضروری نیست
CREATE UNIQUE INDEX IF NOT EXISTS ux_channel_stats_dest_hour
  ON channel_stats(destination_id, hour);
```

## ۴. مراحلِ استقرار
۱. سرویس را متوقف کن: `sudo systemctl stop mrliq-bot`
۲. از دیتابیسِ فعلی یک نسخه‌ی پشتیبانِ دستی بگیر (احتیاطِ همیشگی):
   `cp data/bot.sqlite data/bot.sqlite.bak`
۳. فایل‌های جدید را جایگزین کن (یا کلِ ZIP را استخراج کن روی پوشه‌ی پروژه).
   **`.env` و `data/` و `models/` را از ZIP بازنویسی نکن** — این‌ها مالِ سرورِ توست.
۴. مجوزها را سفت کن (نسخه‌ی جدیدِ `install.sh` خودش این کار را می‌کند، ولی دستی هم می‌شود):
   `chmod 600 .env && chmod 600 data/bot.sqlite`
۵. سرویس را دوباره راه بینداز: `sudo systemctl start mrliq-bot`
۶. لاگِ زنده را چند دقیقه ببین: `journalctl -u mrliq-bot -f`

## ۵. بازگشت به نسخه‌ی قبل (Rollback)
اگر مشکلی دیدی، کافی است فایل‌های قدیمی را برگردانی و سرویس را ری‌استارت کنی.
هیچ‌کدام از تغییراتِ این نسخه فرمتِ دیتابیس را طوری عوض نکرده که با نسخه‌ی قبل
ناسازگار شود، پس بازگشت امن است.

## ۶. تاییدِ سلامتِ بعد از استقرار
- در لاگ باید ببینی: `زمان‌بند فعال شد` و `سرویس مانیتورینگ منابع راه‌اندازی شد`.
- یک بکاپِ دستی بگیر و همان را بازیابی کن؛ باید پیامِ «✅ بازیابی انجام شد» بیاید
  (نه هشدارِ mismatchِ checksum که در نسخه‌ی قبل همیشه می‌آمد).
